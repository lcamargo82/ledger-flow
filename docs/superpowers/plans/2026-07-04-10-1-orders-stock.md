# 10.1 Mercado Livre Orders and Stock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Sprint 10.1.5 by turning Mercado Livre order notifications into idempotent internal orders and stock transitions through existing Orders/Inventory services.

**Architecture:** Keep provider access in the Mercado Livre adapter/client and keep stock effects in Orders/Inventory. Channels owns the intake orchestration: load the inbox event, fetch provider order detail, map provider items to matched `ChannelListing` records, call `OrdersService`, and mark inbox processing outcome. The initial sprint avoids schema changes by using stable channel idempotency keys and existing `ChannelListing.matchedSkuId` plus `ChannelIntegration.defaultWarehouseId`.

**Tech Stack:** NestJS, Prisma, Jest, existing Async handler registry, Mercado Livre adapter/client, OrdersService, ChannelsRepository.
