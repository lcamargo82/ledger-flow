# SDD — 11.0 Sales Intelligence Core

## Boundary

Sales Intelligence is a read layer. Orders own orders, Inventory owns reservations/movements, Financial Intelligence owns operational facts, and 9B owns settlement events/cases.

## API

```text
GET /sales-intelligence
GET /sales-intelligence/summary
```

Both endpoints require `sales-intelligence:read` and `sales_intelligence.read`. The backend derives `tenantId` from the authenticated user.
List and summary accept the same period, order reference, payment status and stock status filters. List pagination is executed in PostgreSQL; summary processing uses bounded batches.

## Money and provenance

Money leaves the API as strings in minor units. `netAmountSource` is mandatory whenever a net value is returned:

```text
REALIZED    → confirmed/released Mercado Pago value ingested by 9B
RECONCILED  → settlement value linked to the order by reconciliation
ESTIMATED   → operational order value less known fees
UNAVAILABLE → source data is insufficient; never coerce to zero
```

## Query strategy

11.0.2 paginates from `InternalOrder`, selects only the current Mercado Livre operational fact, loads item/reservation state and resolves linked Mercado Pago reconciliation cases without N+1 queries. Financial changes create immutable revisions; an SHA-256 signature makes an unchanged replay idempotent, while `isCurrent` identifies the authoritative revision. Revision replacement runs in a serializable transaction and the database enforces one current fact per order.

Stock filtering is derived from `InventoryReservation`: missing, active, consumed and released reservations map to `PENDING`, `RESERVED`, `CONSUMED` and `RELEASED`; mixed item states map to `DIVERGENT`. No parallel stock ledger is created. A materialized snapshot remains deferred until 11.0.4 volume tests justify it.

## Frontend

`SalesIntelligenceView.vue` reuses `AppPageHeader`, `AppCard`, `AppBadge` and `AppEmptyState`. The foundation shell displays no mocked financial data and no profitability fields. The final Core remains responsive and uses existing LedgerFlow tokens and translations.

## Security

- RBAC and capability checks are enforced by backend guards.
- No raw provider payload, secret, buyer-sensitive detail or token is returned.
- Provider IDs remain strings.
- Money is persisted as decimal operational data and serialized as strings in minor units.
- Logs and OpenAPI examples stay sanitized.
