# SDD — 10.1 Mercado Livre Adapter & Omnichannel Operations

## 1. Fronteiras

```text
channels → conexão, OAuth, tokens, listings, webhook, adapter e sync
orders → pedido normalizado/lifecycle
inventory → reserva, release, consume e saldo
catalog → SKU/produto
financial-intelligence → fatos operacionais
platform → tenancy, RBAC, entitlements, audit, async ops, criptografia central
```

O adapter não acessa repositórios internos de Inventory/Orders. Ele produz DTOs normalizados e invoca application services/commands explícitos.

## 2. ChannelIntegration: fonte operacional de conexão

```text
id, tenantId, provider, externalAccountId, displayName
status: ACTIVE | INACTIVE | DISABLED | SUSPENDED | REAUTH_REQUIRED
encryptedCredentials, credentialsVersion, credentialsFingerprint
settingsJson sanitizado, defaultWarehouseId, syncPolicyJson sanitizado
healthStatus, lastSuccessfulOperationAt, lastFailureAt, createdAt, updatedAt
```

Regras:
- `encryptedCredentials` usa exclusivamente o serviço central de criptografia; nenhum crypto específico do provider.
- `settingsJson` não contém access token, refresh token, code ou client secret.
- `credentialsFingerprint` é apenas diagnóstico seguro, nunca token em claro.
- Seleção de integração é explícita; `.env` não é fallback operacional.

## 4. OAuth e token lifecycle

```text
POST /channels/mercado-livre/connect
→ backend cria state seguro
→ Redis: state, tenantId, initiatedByUserId, createdAt, TTL
→ browser redireciona ao provider
→ callback
→ GETDEL/Lua consome state atomicamente
→ valida vínculo tenant/usuário
→ troca code por tokens
→ normaliza credenciais
→ encrypt no serviço central
→ round-trip em memória
→ persistência atômica e versionada em ChannelIntegration
→ audit sanitizado
→ redirect UI
```

### Refresh

```text
Token expirado/próximo de expirar
→ lock distribuído por channelIntegrationId
→ reler versão atual de credenciais
→ refresh backend-only
→ validar resposta
→ encrypt + round-trip
→ update atômico com optimistic version
→ liberar lock
```

### Falha de refresh

```text
inválido/revogado
→ status REAUTH_REQUIRED
→ health degraded
→ jobs externos futuros bloqueados
→ UI pede reconexão
→ sem retry infinito
```

Nunca logar ou expor: authorization code, state completo, tokens, client secret, credentials cifradas, headers completos ou payload OAuth bruto.

## 5. Notifications

```text
POST /webhooks/channels/mercado-livre
→ validar regra oficial configurada
→ ChannelWebhookInboxEvent idempotente
→ OutboxEvent channel.webhook.received
→ 200/202 rápido
→ worker classifica tópico
→ adapter busca detalhes
→ DTO normalizado
→ OrderUpsertFromChannel
→ Inventory reserve/release/consume
```

Inbox contém apenas metadados sanitizados, hash, status e referências necessárias.

## 6. Estoque e sync

```text
InventoryBalance changed
→ localizar listings MATCHED e integração ACTIVE
→ upsert ChannelSyncOperation por coalescingKey
→ Outbox → worker
→ validar status/health da integração
→ RateLimitPolicy
→ updateListingStock(desired state)
→ registrar resultado sanitizado
```

- Enviar estado desejado, nunca delta acumulado.
- 429: Retry-After quando houver; senão backoff+jitter.
- Circuit breaker por integração/provider.
- Impedir sync em SUSPENDED, DISABLED ou REAUTH_REQUIRED.

## 9. 10.1.10 — Configuração operacional

```text
ChannelIntegration.defaultWarehouseId → FK/coluna existente
ChannelIntegration.settingsJson       → syncEnabled, stockSyncMode, importListingsOnConnect
ChannelIntegration.syncPolicyJson     → rate/coalescing policy sanitizada
```

Não duplicar `defaultWarehouseId` em JSON. `PATCH /channels/integrations/:id/settings` valida warehouse ativo do tenant e usa DTO allowlisted. Import listing não exige warehouse; order intake falha com código estável e ação de configuração quando ele estiver ausente.

Projeção de health:

```text
ACTIVE + operação recente              → HEALTHY
ACTIVE + falhas transitórias           → DEGRADED
REAUTH_REQUIRED                        → REAUTH_REQUIRED
SUSPENDED                              → SUSPENDED
DISABLED ou credenciais removidas      → DISCONNECTED
falha persistente não classificável    → FAILED
```

Callback público continua protegido por state one-time/TTL e redireciona somente para origem frontend allowlisted. Query de retorno contém status/código, nunca code/state/token.

## 10. 10.1.11 — Order Financial & Shipping Enrichment

Criar `OrderShippingSummary` one-to-one por order/provider com `externalShipmentId` string, status/substatus, shipping mode, handling/delivery estimates, postedAt, tracking mascarado, source, confidence e lastSyncedAt. Valores financeiros continuam em `OrderFinancialFact` e usam Decimal/minor units.

Adapter expõe DTO normalizado; não persiste payload bruto. Upsert é idempotente por tenant/order/provider. Mudança relevante publica timeline/outbox uma vez e alimenta Notification Center/outbound delivery conforme ADR 0038.
