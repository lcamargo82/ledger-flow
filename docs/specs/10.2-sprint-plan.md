# Spec — Plano de Sprints 10.2

**Status:** planejado. Uma branch dedicada por sprint; merge em `develop` somente após Definition of Done.

## Dependências

```text
10.1.10 operacional
→ 10.2.0A internal notifications
→ 10.2.0B outbound delivery
→ 10.2.1 inventory foundation
→ 10.2.2 transfers
→ 10.2.3 cycle counts
→ 10.1.11 ML enrichment
```

10.2.0B pode avançar em paralelo com 10.2.1 após congelar o contrato `NotificationEvent`, mas o caminho recomendado é sequencial.

## 10.2.0A — Notification Center interno

- Schema event/recipient, registry de categorias e audiência RBAC/capability.
- APIs paginadas, unread count, read/read-all/dismiss.
- Sino, versão e `/notifications`.
- Producers mínimos: falha de canal e divergência de conciliação, sob feature flag.
- Testes cross-tenant, permissão revogada, duplicata e paginação.
- Swagger/Redoc, i18n, README/UI docs e ADR 0036.

**Aceite:** contador/lista convergem; usuário vê apenas conteúdo autorizado; badge/footer funciona expandido e colapsado.

## 10.2.0B — Outbound webhooks para automação

- Subscription/delivery, segredo cifrado, assinatura HMAC e antireplay.
- Dispatcher Outbox/worker, retry/backoff/DLQ/replay.
- Endpoint de teste sem PII e métricas de entrega.
- AsyncAPI e runbook de rotação/diagnóstico.

**Aceite:** n8n valida assinatura, deduplica por idempotency key e indisponibilidade não perde nem duplica semanticamente o evento.

## 10.2.1 — Advanced Inventory Foundation

- Capabilities/permissões, seeds idempotentes e reason-code registry.
- Contratos/repositories e feature flags para transfers/cycle counts.
- Rotas/menu somente quando a feature estiver habilitada; placeholder não pode aparentar funcionalidade concluída.
- Documentar migrations, APIs, estados e componentes.

**Aceite:** nenhuma alteração de saldo; acesso negado no backend e frontend quando entitlement faltar.

## 10.2.2 — Transferências

- Migration `InventoryTransfer`/items.
- Create/list/detail/update draft/start/complete/cancel.
- Transação com dois movimentos, audit/outbox/notification.
- UI lista, formulário multi-item, detalhe e confirmações.
- Testes concorrentes, saldo insuficiente, idempotência, rollback e cross-tenant.

**Aceite:** conclusão não produz efeito unilateral e não permite saldo negativo.

## 10.2.3 — Inventário cíclico

- Migration `CycleCount`/items e snapshot de versão.
- Create/list/detail/open/count/approve/cancel.
- Aprovação atômica e bloqueio de snapshot stale.
- UI de contagem com resumo de divergência e confirmação de ajuste.
- Notifications, audit, Swagger/Redoc e AsyncAPI.

**Aceite:** contagem só altera saldo após aprovação autorizada; cada divergência possui motivo e movimento rastreável.

## Definition of Done por sprint

1. Testes RED/GREEN e regressão do módulo afetado.
2. `prisma validate`, migration test e rollback operacional documentado quando houver schema.
3. API build/lint e Web type-check/build.
4. `npm run i18n:check` e ausência de hardcode nas superfícies novas.
5. Swagger/Redoc com DTOs/exemplos/erros e autorização.
6. AsyncAPI somente para eventos realmente publicados/consumidos.
7. README, docs index, PRD/SDD/backlog/runbook/UI atualizados.
8. Logs/audit sanitizados e testes cross-tenant/RBAC/capability.
