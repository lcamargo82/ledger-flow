# Spec — 11.0 Sales Intelligence Core Sprint Plan

## 11.0.1 — Foundation

**Status:** Implemented on `feature/11-0-1-sales-intelligence-foundation`.

- Module, DTOs and feature-safe empty endpoints.
- `sales-intelligence:read` plus `sales_intelligence.read`.
- Protected `/sales-intelligence` route, navigation and pt-BR/en-US shell.
- Swagger/Redoc/OpenAPI contracts without profitability data.

## 11.0.2 — Read model

**Status:** Implemented on `feature/11-0-2-sales-intelligence-read-model`.

- Persist payment status/value and expected net as idempotent financial revisions.
- Consolidate order, latest operational fact, 9B net provenance and inventory state.
- Cover realized, reconciled, estimated and unavailable values.
- Paginate and filter in the database; calculate summaries in bounded batches.

## 11.0.3 — Sales queue

**Status:** Implemented on `feature/11-0-3-sales-intelligence-ui`.

- One row per order, summary and approved filters.
- Drawer with grouped SKUs, quantities and stock state per item.
- Reusable components and explicit provenance badges.
- Idempotent permission migration for existing tenants; `OWNER` receives the tenant permission while custom roles remain explicit.
- Responsive application shell with off-canvas mobile navigation.

## 11.0.4 — Closure

**Status:** Implemented on `feature/11-0-4-sales-intelligence-hardening`.

- Query/index validation, tenant security review and cursor-batched large-range summaries.
- Production dependency baseline resolved with Multer 2.2.0 and js-yaml 4.3.0.
- Shared responsive metric components align Analytics with Sales Intelligence.
- Focused API/web tests, builds, i18n, runtime smoke and operational documentation complete.

Each sprint branches from `feature/11-0-sales-intelligence`, returns to it with `--no-ff`, and the base reaches `develop` only after 11.0.4 passes.
