# 11.0.4 Security Assessment

**Date:** 2026-07-14  
**Scope:** Sales Intelligence Core, Analytics metric refactor and production dependency baseline

## Result

No new critical or high security finding remains in the 11.0.4 scope.

- `npm audit --omit=dev`: zero production vulnerabilities after upgrading to Multer 2.2.0 and js-yaml 4.3.0 through compatible Nest 11 releases.
- Both Sales Intelligence endpoints require JWT authentication, `sales-intelligence:read` and `sales_intelligence.read`.
- The controller derives `tenantId` only from `CurrentUser`; DTOs do not accept it.
- Prisma queries are parameterized, tenant-scoped, field-selected and bounded.
- Responses omit raw provider payload, tokens, secrets, buyer-sensitive data, cost and profit.
- Unauthenticated runtime request returns `401`; authorization and tenant derivation have focused tests.

## Automated scanner triage

The repository-wide heuristic scanner reported strings in test fixtures as tokens, local Redis URLs as database connection strings, and ioredis `.exec()`/`.eval()` methods as JavaScript dynamic execution. Manual review classified these as false positives:

- token strings are synthetic fixtures used to verify redaction;
- `redis://localhost:6379` has no credential and is only a development fallback;
- Redis `MULTI.exec()` and the parameterized Lua lock release are not JavaScript `eval`/process execution;
- `document.body.innerHTML = ''` is test cleanup, not user-content rendering;
- findings inside the scanner source are its own detection patterns.

## Inherited platform baseline

The scanner also repeated the pre-existing medium finding that global HTTP security headers are not configured explicitly in the Nest bootstrap. This affects the entire API, including Swagger/Redoc CSP compatibility, and is already documented as platform-wide hardening rather than a Sales Intelligence defect. It should be implemented and regression-tested as an isolated security task instead of changing every API response inside the 11.0 Core closure.

The permissive development CORS baseline follows the same platform-wide boundary and must be restricted per deployment environment in that task.
