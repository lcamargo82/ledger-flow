# Runbook — 11.0 Sales Intelligence Operational Readiness

## Objetivo

Validar a publicação do Core de Inteligência de vendas sem expor dados sensíveis ou alterar a operação manual de pedidos.

## Pré-requisitos

- Migrations aplicadas com `npm run prisma:deploy` na API.
- Tenant ativo `ENTERPRISE` ou `CUSTOM`, necessário para `sales_intelligence.read`.
- Usuário com `sales-intelligence:read`. A migration associa a permissão às roles `OWNER`; roles personalizadas exigem atribuição administrativa explícita.
- Nova sessão após mudança de plano, role ou permissão.

Não é necessário executar a seed geral após a migration em ambientes existentes.

## Validação técnica

Na API:

```bash
npx prisma validate
npm run prisma:generate
npm test -- --runInBand src/modules/sales-intelligence
npm run build
npm audit --omit=dev
```

No frontend:

```bash
npm run test:unit -- --run
npm run type-check
npm run lint
npm run i18n:check
npm run build
```

## Smoke autenticado

1. Confirmar `200` e o tag `Sales Intelligence` em `/api/openapi.json`, `/api/docs` e `/api/reference`.
2. Abrir `/sales-intelligence` com usuário autorizado e confirmar resumo, filtros, paginação e drawer.
3. Confirmar que uma venda aparece uma vez por pedido e que seus SKUs ficam apenas no drawer.
4. Confirmar a prioridade `REALIZED`, `RECONCILED`, `ESTIMATED`, `UNAVAILABLE` e o rótulo explícito da origem.
5. Confirmar que o Analytics exibe quatro indicadores compactos no mesmo padrão visual do resumo de vendas.
6. Repetir em viewport mobile e confirmar menu off-canvas, cards responsivos e tabela com rolagem horizontal.

## Segurança e dados

- O cliente nunca envia nem escolhe `tenantId`; a API deriva o tenant da sessão autenticada.
- Os endpoints exigem permission e capability no backend, além do bloqueio de rota no frontend.
- Respostas não contêm token, segredo, payload bruto do provider, dados sensíveis do comprador, custo ou lucro.
- Valores monetários permanecem strings em minor units na API; a UI faz apenas a apresentação localizada.
- Falhas exibem mensagens traduzidas e sanitizadas, sem repassar exceções internas.

## Rollback

- Reverter a release da aplicação para o artefato anterior.
- Não remover fatos financeiros, reservas ou settlements: Sales Intelligence é uma camada de leitura e não possui ledger próprio.
- A permission adicionada pode permanecer cadastrada sem conceder acesso quando capability/role não autorizarem.
